# 调度实验台

操作系统进程调度可视化模拟器。调度核心在 `src/core`，不依赖界面。界面只把核心输出的时间片画成甘特图，并在图下印出同一串片段，例如 `P1[0,7) P2[7,11)`。半开区间 `[start, end)` 表示从时刻 start 执行到 end，不含 end。

规范原文在本目录的 `task-04-scheduler-simulator.md`。

## 如何运行

需要 Node.js 20 或更高版本。

```bash
cd task-04-scheduler-simulator
npm ci
npm run dev          # http://127.0.0.1:5173
npm run typecheck
npm test             # Vitest，核心与手算夹具
npm run build
npm run test:e2e     # Playwright，需先 build；会写 screenshots/
npm run test:all     # 类型检查 + 单元测试 + 构建 + 端到端
```

界面打开后默认是用例 A、先来先服务。可以改进程表、切换算法、单步或按速度播放，也可以在运行中追加进程。进程表可以从 JSON 或 CSV 导入，也可以按种子生成。跑过之后，时间轴可以拖回任意已经记录的时刻。对比报告用当前进程表，从 t=0 把勾选的算法各自跑完，并画出平均等待、周转、响应的柱状图。

## 调度约定

下面这几条是核心、手算夹具和界面共用的合同。`src/core/rules.ts` 里的 `RULES_SUMMARY` 是同一段话。

时间是离散整数。时刻 t 按这个顺序处理：

1. 到达时间等于 t 的进程，按 PID 升序，进入就绪队列队尾。
2. 抢占式算法检查就绪进程。只有主关键字**严格更优**才抢占。SRTF 比剩余时间，抢占式优先级比优先级数值，MLFQ 比是否存在更高队列。相等不抢占。
3. CPU 空闲则分派下一进程。
4. 执行区间 `[t, t+1)`。
5. 这一拍结束时：剩余时间到 0 则完成；否则若 CPU 进度到达 I/O 触发点则进入等待；否则若时间片用尽则让出 CPU。

时间片用尽发生在上一拍结束，所以让出的进程先入队，然后才处理时刻 t 的新到达。被抢占的进程也在时刻 t 的第 2 步入队，排在这一刻新到达的进程之前。

平局：先比较到达时间，更早者优先；到达时间也相同则 PID 更小者优先。FCFS 不看服务时间和优先级，只按入队顺序；同时到达时第 1 步已经按 PID 排好。

优先级数值越小越高。

甘特图的一段是一次分派。同一进程在时间片边界被再次分派时，两段不合并。连续空闲合并成一段。

指标：

| 指标 | 定义 |
| --- | --- |
| 周转时间 | 完成时间 − 到达时间 |
| 等待时间 | 停留在就绪态的时间，等于周转 − 服务时间 − I/O 时间 − 切换开销。不含 I/O 阻塞，不含尚未到达的新建态，也不含正在切换的时间 |
| 响应时间 | 首次执行服务的时刻 − 到达时间。上下文切换不算服务，所以开头的切换会推迟响应 |
| CPU 利用率 | 服务时间 / 仿真时钟。时钟从 0 算到最后一个进程完成，开头和中间的空闲、以及上下文切换都算在分母里，分子只算真正消耗的服务时间 |
| 平均值 | 只统计已完成进程。界面保留两位小数 |

没有 I/O、切换开销为 0 时，等待时间 = 周转时间 − 服务时间。用例 A/B/C 就是这种情况。第三轮的切换用例改为：等待 = 周转 − 服务 − 切换开销。

上下文切换、优先级老化和 MLFQ 提升默认都是 0。保持关闭时，用例 A/B/C 的片段和四个时间指标与第二轮相同。加载任一预设都会把这三个旋钮写成该预设的值；A/B/C/Q1/I/O 没有另写时就是 0，避免上一次的切换开销漏进标准用例。

动态添加：仿真还没走步时，使用填写的到达时间。时钟已经走动之后，早于当前时间的到达被调整到当前时间，进程仍是新建态，下一步才入队。未来到达保持原值。请求对象本身不会被改写。

## 算法

### 先来先服务 FCFS

就绪队列先进先出，不抢占。同时到达按 PID 升序入队。服务时间更短或优先级更高都不会插队。

### 短作业优先 SJF（非抢占）

只在 CPU 空闲时选择。比较的是**当前剩余 CPU 时间**（没有运行过、也没有 I/O 时等于服务时间）。剩余时间相同则先到达时间，再 PID。选中后一直运行到完成、进入 I/O，或仿真结束，中途不抢占。

### 最短剩余时间优先 SRTF

空闲时的选择规则与 SJF 相同。运行中，只有某个就绪进程的剩余时间**严格更短**才抢占。剩余时间相等时当前进程继续，即使对方 PID 更小。

### 时间片轮转 RR

就绪队列先进先出。时间片是整数，至少为 1，界面和对比报告都可以改，默认 2。时间片用尽后进入队尾，并清零已用时间片。若队列里只剩它自己，下一拍会再次分派，甘特图仍分成两段。I/O 返回后时间片重新计算，从队尾开始。

### 优先级（非抢占 / 抢占）

两种都要实现，界面里是两个独立算法。数值越小越高。空闲时选择最高优先级；平局先到达时间，再 PID。

非抢占：选中后不被后来的更高优先级打断。

抢占：只有就绪进程的优先级数值**严格更小**才抢占。数值相等不抢占。

老化间隔 N 默认为 0，表示关闭，比较的仍是原始优先级。N ≥ 1 时，有效优先级 = 原始优先级 − floor(就绪等待 / N)。只在就绪态累积等待，运行、切换、I/O 和尚未到达都不增加这份等待，所以正在运行的进程不会自己变好。抢占仍然要求有效优先级**严格更小**；仅仅追平不抢占。平局仍是先到达时间，再 PID。N 同时作用于非抢占和抢占两种优先级算法，不作用于 HRRN 或 MLFQ。

### 最高响应比优先 HRRN（非抢占）

只在 CPU 空闲时选择。响应比 = (就绪等待 + 原服务时间) / 原服务时间。刚到达的进程等待为 0，响应比是 1。比较时用交叉相乘，(w1 + b1) × b2 与 (w2 + b2) × b1，避免小数。响应比更大者优先；相等则先到达时间，再 PID。选中后不被抢占。服务时间用进程原来的服务时间，不用剩余时间。

### 多级反馈队列 MLFQ

默认 3 级，时间片 2 / 4 / 8。队列可以增加到 3 级以上，每级时间片是不小于 1 的整数。Q0 最高。

- 新进程进入 Q0 队尾。
- 时间片用尽：若不是最低级则降一级，已用时间片清零，进入该级队尾。最低级用尽后留在最低级队尾。
- 更高队列来了进程：当前进程回到**本队队首**，已用时间片保留，不降级。
- I/O 返回：留在原级，时间片清零，进入队尾。
- 分派时从最高的非空队列取队首。
- 进程属性里的优先级字段不参与 MLFQ。
- 提升周期 S 默认为 0。S ≥ 1 时，在每个正的倍数时刻（t = S, 2S, …，不含 t = 0）、处理这一刻的到达之前，所有已经到达且未完成的进程回到 Q0，已用时间片清零。就绪队列按 Q0、Q1、… 的原顺序接成 Q0。正在运行的进程留在 CPU 上，但级别回到 Q0，时间片重新计算，因此同一次运行可以跨过提升点并成一段。正在等待 I/O 的进程仍在等待，返回时进入 Q0。尚未到达的进程保持新建。

### 上下文切换

切换耗时 c 默认为 0，甘特图里不出现切换段。c > 0 时，每次**重新分派**先占用 CPU c 个时间单位，包括第一次从空闲分派，以及同一进程让出后再次上场。同一进程连续运行到下一拍不另计切换。切换期间该进程处于运行态，所以不累积就绪等待，也不算首次服务；`firstStart` 记在切换结束后的第一拍服务上。切换段的 pid 为空，并带 `switch: true`。连续的切换拍合并成一段。切换不是空闲。CPU 利用率的分子不含这些拍。

## 用例 A：错开到达

| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 0 | 7 | 2 |
| 2 | 2 | 4 | 1 |
| 3 | 4 | 1 | 3 |
| 4 | 5 | 4 | 2 |

RR 时间片 2。MLFQ 时间片 2/4/8。没有 I/O。四个进程的服务时间之和是 16，每种算法都没有空闲，CPU 利用率为 100%。

### FCFS

P1 在 0 到达并运行到 7。P2、P3、P4 按到达顺序排在后面。P1 完成后依次运行 P2、P3、P4。

`P1[0,7) P2[7,11) P3[11,12) P4[12,16)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 7 | 7 | 0 | 0 |
| 2 | 11 | 9 | 5 | 5 |
| 3 | 12 | 8 | 7 | 7 |
| 4 | 16 | 11 | 7 | 7 |

平均等待 4.75，平均周转 8.75，平均响应 4.75。

### SJF（非抢占）

P1 从 0 运行到 7，中途不看新到达。t=7 时剩余时间是 P3=1、P2=4、P4=4。先选 P3。P2 与 P4 剩余时间相同，P2 到达更早。

`P1[0,7) P3[7,8) P2[8,12) P4[12,16)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 7 | 7 | 0 | 0 |
| 2 | 12 | 10 | 6 | 6 |
| 3 | 8 | 4 | 3 | 3 |
| 4 | 16 | 11 | 7 | 7 |

平均等待 4.00，平均周转 8.00，平均响应 4.00。

### SRTF

- t=0：只有 P1，剩余 7。
- t=2：P2 到达，剩余 4，P1 还剩 5。4 更小，抢占。P1 已运行 `[0,2)`。
- t=4：P3 到达，剩余 1，P2 还剩 2。抢占。P2 已运行 `[2,4)`。
- t=5：P3 完成。就绪进程剩余时间 P2=2、P4=4、P1=5，选 P2。P2 运行 `[5,7)` 后完成。
- t=7：P4 剩余 4，P1 剩余 5，选 P4，运行 `[7,11)`。
- t=11：P1 运行 `[11,16)`。

t=2 时两者剩余时间如果相等就不会抢占；这里是 4 < 5，所以抢占。

`P1[0,2) P2[2,4) P3[4,5) P2[5,7) P4[7,11) P1[11,16)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 16 | 16 | 9 | 0 |
| 2 | 7 | 5 | 1 | 0 |
| 3 | 5 | 1 | 0 | 0 |
| 4 | 11 | 6 | 2 | 2 |

平均等待 3.00，平均周转 7.00，平均响应 0.50。

### RR，q=2

队列变化（队首在左）：

| 时刻 | 发生的事 | 随后的队列 |
| --- | --- | --- |
| 0 | P1 入队并被分派 | 空 |
| 2 | P1 时间片用尽，先入队；然后 P2 到达 | 分派 P1，队列 `[P2]` |
| 4 | P1 再次用尽；P3 到达 | 分派 P2，队列 `[P1, P3]` |
| 5 | P4 到达，P2 仍在运行 | `[P1, P3, P4]` |
| 6 | P2 用尽 | 分派 P1，队列 `[P3, P4, P2]` |
| 8 | P1 用尽，还剩 1 | 分派 P3，队列 `[P4, P2, P1]` |
| 9 | P3 完成 | 分派 P4，队列 `[P2, P1]` |
| 11 | P4 用尽，还剩 2 | 分派 P2，队列 `[P1, P4]` |
| 13 | P2 完成 | 分派 P1，队列 `[P4]` |
| 14 | P1 完成 | 分派 P4 |
| 16 | P4 完成 | 空 |

| --- | --- | --- | --- | --- |
| 1 | 14 | 14 | 7 | 0 |
| 2 | 13 | 11 | 7 | 2 |
| 3 | 9 | 5 | 4 | 4 |
| 4 | 16 | 11 | 7 | 4 |

平均等待 6.25，平均周转 10.25，平均响应 2.50。

P1 优先级 2，从 0 运行到 7。t=7 的优先级是 P2=1、P4=2、P3=3。先 P2，再 P4，最后 P3。

`P1[0,7) P2[7,11) P4[11,15) P3[15,16)`

| 4 | 15 | 10 | 6 | 6 |

### MLFQ，q=2/4/8

- `[0,2)` P1 用完 Q0，降到 Q1。
- t=2，P2 进入 Q0，运行 `[2,4)`，降到 Q1。此时 Q1 是 `[P1, P2]`。
- t=4，P3 进入 Q0，服务时间只有 1，运行 `[4,5)` 后完成。
- t=5，P4 进入 Q0，运行 `[5,7)`，降到 Q1。Q1 是 `[P1, P2, P4]`。
- P1 在 Q1 还剩 5，时间片 4，运行 `[7,11)` 后降到 Q2，还剩 1。
- P2 在 Q1 还剩 2，运行 `[11,13)` 完成。
- P4 在 Q1 还剩 2，运行 `[13,15)` 完成。
- P1 在 Q2 运行 `[15,16)` 完成。

`P1[0,2) P2[2,4) P3[4,5) P4[5,7) P1[7,11) P2[11,13) P4[13,15) P1[15,16)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 16 | 16 | 9 | 0 |
| 2 | 13 | 11 | 7 | 0 |
| 3 | 5 | 1 | 0 | 0 |
| 4 | 15 | 10 | 6 | 0 |

平均等待 5.50，平均周转 9.50，平均响应 0.00。四个进程都在到达的那一拍立刻上了 Q0，所以响应时间都是 0。

## 用例 B：同时到达

| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 0 | 4 | 2 |
| 2 | 0 | 6 | 1 |
| 3 | 0 | 2 | 3 |
| 4 | 0 | 6 | 1 |

## 用例 C：单个进程

| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 4 | 5 | 2 |

`[0,4)` 是空闲。空闲不算等待。完成时间 9，周转 5，等待 0，响应 0。忙碌 5、时钟 9，CPU 利用率 5/9 = 55.56%。七种算法的这三个时间指标都一样，差别在甘特图是否因时间片被切开：

| 算法 | 甘特图 |
| --- | --- |
| FCFS、SJF、SRTF、两种优先级 | `空闲[0,4) P1[4,9)` |
| RR q=2 | `空闲[0,4) P1[4,6) P1[6,8) P1[8,9)` |
| MLFQ 2/4/8 | `空闲[0,4) P1[4,6) P1[6,9)` |

RR 三次分派是因为 q=2，最后一段只剩 1。MLFQ 先在 Q0 运行 2，再降到 Q1，剩余 3 小于该级时间片 4，所以第二段是 `[6,9)`。

| Q1 | (1,0,3,1) (2,0,2,1) (3,1,2,1) | RR q=1 | `P1[0,1) P2[1,2) P1[2,3) P3[3,4) P2[4,5) P1[5,6) P3[6,7)` | 时间片为 1。t=1 时 P1 先回到队尾，P3 再到达，所以顺序是 P2、P1、P3 |
| SRTF-TIE | (1,0,4,1) (2,2,2,1) | SRTF | `P1[0,4) P2[4,6)` | t=2 时两者剩余都是 2，不抢占 |
| SRTF-PREEMPT | (1,0,4,1) (2,2,1,1) | SRTF | `P1[0,2) P2[2,3) P1[3,5)` | t=2 时 1 < 2，抢占 |

| PRI-PREEMPT | (1,0,5,2) (2,1,1,1) | 优先级·抢占 | `P1[0,1) P2[1,2) P1[2,6)` | 1 严格小于 2，抢占 |

| SJF-PID | (1,0,4,1) (2,1,3,1) (3,1,3,1) | SJF | `P1[0,4) P2[4,7) P3[7,10)` | 到达时间也相同，PID 升序 |

| IDLE-GAP | (1,0,2,1) (2,5,2,1) | FCFS | `P1[0,2) 空闲[2,5) P2[5,7)` | P2 的等待和响应都是 0，中间空闲不记入等待 |

## 用例 D：响应比与老化

| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 0 | 10 | 4 |
| 2 | 1 | 10 | 5 |
| 3 | 9 | 2 | 2 |

P1 先独自运行到 10。t=10 时 CPU 空闲，P2 已等待 9，P3 已等待 1。

HRRN：P2 的响应比 (9+10)/10 = 1.9，P3 的 (1+2)/2 = 1.5，所以先 P2 再 P3。

`P1[0,10) P2[10,20) P3[20,22)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 10 | 10 | 0 | 0 |
| 2 | 20 | 19 | 9 | 9 |
| 3 | 22 | 13 | 11 | 11 |

关闭老化时，SJF 和非抢占优先级都在 t=10 选择更短、优先级数值更小的 P3：

`P1[0,10) P3[10,12) P2[12,22)`

P1 为 10/10/0/0，P2 为 22/21/11/11，P3 为 12/3/1/1。这组和 HRRN 不同，用来确认响应比不是最短作业。

关闭老化的抢占优先级：t=9 时 P3 的 2 严格小于 P1 的 4，抢走 CPU。P3 跑完两拍，P1 再补最后 1 拍，然后才是 P2。

`P1[0,9) P3[9,11) P1[11,12) P2[12,22)`

P1 为 12/12/2/0，P2 为 22/21/11/11，P3 为 11/2/0/0。

非抢占老化 N=2：决策只发生在 t=10。P2 的有效优先级是 5 − floor(9/2) = 1，P3 仍是 2。1 更优，所以顺序和 HRRN 相同，原因不同：`P1[0,10) P2[10,20) P3[20,22)`，三个进程的四个时间也与上表相同。

抢占老化 N=2。有效优先级 = 优先级 − floor(就绪等待 / 2)，更小才抢占，相等则先到达时间。运行中的等待冻结。

| 时刻 | 就绪等待与有效优先级 | 决定 |
| --- | --- | --- |
| 0 | P1 等待 0，有效 4 | P1 开始运行 |
| 5 | P2 自 t=1 起等待 4，有效 5−2=3，小于 P1 的 4 | P2 抢走 CPU。P1 已运行 5 |
| 9 | P1 又等待 4，有效 2。P3 刚到，有效 2。二者都小于正在运行的 P2（有效 3） | 到达更早的 P1 上台，不是 P3。P2 已再运行 4，剩余 6 |
| 11 | P3 等待 2，有效 1，小于 P1 的 2 | P3 上台。P1 累计已运行 7，剩余 3 |
| 13 | P3 在 [11,13) 跑完。P1 有效 1，P2 有效 1 | 到达更早的 P1 继续 |
| 15 | P2 等待累计 10，有效 0，小于 P1 的 1 | P2 上台。P1 累计已运行 9，剩余 1 |
| 19 | P1 有效 −1，小于 P2 的 0 | P1 跑完最后 1 拍，完成于 20 |
| 20 | 只剩 P2，剩余 2 | P2 在 [20,22) 完成 |

`P1[0,5) P2[5,9) P1[9,11) P3[11,13) P1[13,15) P2[15,19) P1[19,20) P2[20,22)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 20 | 20 | 10 | 0 |
| 2 | 22 | 21 | 11 | 4 |
| 3 | 13 | 4 | 2 | 2 |

t=9 这一行是手算时容易漏的地方：P3 的原始优先级更好，但 P1 已经老化到同一个有效优先级 2，平局归更早到达的 P1。

响应比的另一个平局：P1 在 0 到达、服务 5；P2 和 P3 都在 2 到达、服务都是 4。t=5 时两人等待都是 3、服务都是 4，响应比相同，PID 更小的 P2 先运行。片段是 `P1[0,5) P2[5,9) P3[9,13)`。

## 用例 E：切换开销为 1

| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 0 | 4 | 2 |
| 2 | 0 | 3 | 1 |
| 3 | 6 | 2 | 3 |

c=1。每次重新分派先付 1 拍切换。FCFS 按 PID 处理 t=0 的同时到达，所以先 P1。

`切换[0,1) P1[1,5) 切换[5,6) P2[6,9) 切换[9,10) P3[10,12)`

| PID | 完成 | 周转 | 等待 | 响应 | 切换 |
| --- | --- | --- | --- | --- | --- |
| 1 | 5 | 5 | 0 | 1 | 1 |
| 2 | 9 | 9 | 5 | 6 | 1 |
| 3 | 12 | 6 | 3 | 4 | 1 |

服务时间合计 9，完成时刻 12，CPU 利用率 9/12 = 75%。等待 = 周转 − 服务 − 切换。例如 P2：9 − 3 − 1 = 5，这 5 拍是它在就绪队列里等 P1 的切换和运行。它自己的切换拍算运行态，不进等待，但响应要等到切换后的第一拍服务，所以响应是 6。

同一组进程、RR、q=2。让出的进程先回队尾，然后才处理这一刻的新到达。

| 时刻 | 队列与决定 |
| --- | --- |
| 0 | P1、P2 按 PID 入队。先切换到 P1 |
| 1–3 | P1 得到 2 拍服务，时间片用尽，排到当时只剩 P2 的队尾 |
| 3–6 | 切换到 P2，P2 得到 2 拍，剩余 1，在 t=6 之前回队尾 |
| 6 | P3 在 P2 回队之后到达。队列是 P1、P2、P3。切换到 P1 |
| 7–9 | P1 跑完剩余 2 拍，完成 |
| 9–11 | 切换到 P2，P2 跑完最后 1 拍 |
| 11–14 | 切换到 P3，P3 跑完 2 拍 |

`切换[0,1) P1[1,3) 切换[3,4) P2[4,6) 切换[6,7) P1[7,9) 切换[9,10) P2[10,11) 切换[11,12) P3[12,14)`

| PID | 完成 | 周转 | 等待 | 响应 | 切换 |
| --- | --- | --- | --- | --- | --- |
| 1 | 9 | 9 | 3 | 1 | 2 |
| 2 | 11 | 11 | 6 | 4 | 2 |
| 3 | 14 | 8 | 5 | 6 | 1 |

完成时刻 14，利用率 9/14。c=0 时同一组 FCFS 没有切换段：`P1[0,4) P2[4,7) P3[7,9)`。

只剩一个进程时，时间片用尽后再次上场也要再付切换。P1 到达 0、服务 5、q=2、c=1：`切换[0,1) P1[1,3) 切换[3,4) P1[4,6) 切换[6,7) P1[7,8)`。三次切换，利用率 5/8。

## 用例 F：MLFQ 提升

P1 和 P2 都在 0 到达，服务分别是 6 和 4，时间片 2/4/8。

不提升时，两人先各用完 Q0 的 2，降到 Q1。Q1 的时间片是 4，P1 把剩余 4 一次跑完，然后 P2 跑完剩余 2：

`P1[0,2) P2[2,4) P1[4,8) P2[8,10)`

提升周期 S=4。t=0 不提升。t=4 时两人已经都在 Q1，按原顺序 P1、P2 回到 Q0，时间片清零。P1 再用掉 Q0 的 2 并降级；P2 的剩余正好是 2，在 Q0 跑完。t=8 时 P1 再被送回 Q0，跑完最后 2 拍。

`P1[0,2) P2[2,4) P1[4,6) P2[6,8) P1[8,10)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 10 | 10 | 4 | 0 |
| 2 | 8 | 8 | 4 | 2 |

S=0 时片段回到不提升的那一组。

## 动态添加与 I/O

用例 A 跑到 t=3 时加入 P5，请求到达时间 0、服务时间 2、优先级 1。因为时钟已经是 3，有效到达时间改成 3。FCFS 队列在 P1 完成后是 P2、P5、P3、P4：

`P1[0,7) P2[7,11) P5[11,13) P3[13,14) P4[14,18)`

P5 完成 13，周转 10，等待 8，响应 8。端到端测试检查这一段。

I/O 示例：P1 到达 0、服务 4，累计 CPU 满 2 后阻塞 3；P2 到达 0、服务 3。FCFS：

`P1[0,2) P2[2,5) P1[5,7)`

P1 完成 7、周转 7、等待 0、响应 0、I/O 3。P2 完成 5、周转 5、等待 2、响应 2。平均等待 1.00，平均周转 6.00，平均响应 1.00。阻塞的 3 个时间单位不算等待。t=2 这一拍结束时 P1 刚进入等待，P2 还在队首，下一步才分派 P2，最终甘特图里没有空闲段。

## 界面在检查什么

- 甘特图每一块的 `data-pid`、`data-start`、`data-end` 与核心片段一一对应，图下的文字是同一串片段。切换段的 `data-pid` 是 `switch`，`data-switch` 是 `true`，文字写成 `切换[start,end)`，颜色和空闲不同。
- 同色块之间的空隙表示再次分派，不是空闲。空闲用斜线单独画出来。
- 当前运行进程、就绪队列队首、I/O 等待队列、每个进程的状态文字和状态泳道会随单步更新。时间轴拖回过去时，这些区域显示那一时刻的快照；添加进程仍按已经走到的仿真时间。
- 速度有暂停、慢放（2 秒一步）、正常（0.8 秒）、快进（0.12 秒），另有单步和运行至结束。回看时单步只前进到下一条记录；播放从当前仿真继续。
- 导出 JSON 是完整的 `SimulationResult`。导出 CSV 含 `process`、`slice`、`summary` 三种行；`cpu_utilization` 是 0 到 1 的比值，不是百分数。`summary` 的完成时刻在 `makespan` 列。
- 对比表、柱状图和每张对比甘特图都从核心重新计算。柱状图是平均等待、平均周转、平均响应。对比可以另存 CSV（`algorithm,avg_waiting,avg_turnaround,avg_response,cpu_utilization,makespan`）和带打印样式的 HTML。HRRN 默认不勾选，因此不改参数时导出的算法顺序仍是原来的七种。改时间片、切换、老化或提升后要点「生成对比报告」。加载预设会恢复该预设的时间片，并把切换、老化和提升写成预设值；A/B/C 不改当前选中的算法。
- JSON 可以是进程数组，或 `{ "processes": [...] }`。CSV 第一行必须有 `pid`、`arrival`（或 `arrivalTime`）、`burst`（或 `burstTime`、`service`）、`priority`。错误按行或按进程序号全部列出，有任何错误就不替换当前进程表。随机生成使用 mulberry32，同一整数种子得到同一张表。

## 已知限制

- 只有一个 CPU，时间只能是整数。
- 界面上每个进程只能填一次 I/O。引擎可以接收同一进程的多次 I/O，触发点必须满足 `1 ≤ afterCpu < 服务时间`，且不能重复。
- I/O 返回后，RR 和 MLFQ 都重新计算时间片。没有到提升点时，MLFQ 不升回 Q0，也不降级。提升点会把正在等待的进程标记回 Q0，所以它返回时进入最高队列。
- 优先级老化只作用于两种优先级算法。MLFQ 不读取进程优先级；它的周期性提升是另一件事，默认关闭。
- 导出和对比都按当前进程表从 t=0 重新跑完，不是把播放头截成半成品。动态添加过的进程使用调整后的到达时间。时间轴只回看已经走过的快照，不能把引擎倒回那个时刻再分叉。
- 导入是整表替换。任一字段错误都会放弃整份文件，并保留原来的进程表。JSON 的序号是进程在数组中的位置，从 1 起算，不是文件的物理行号。随机进程数量是 1 到 20。
- 平均指标在有进程完成之前显示为「—」。
- 同一拍里，时间片用尽或 I/O 结束先入队，这一拍的新到达排在后面。若按「新到达先于让出进程」来手算 RR，结果会和这里不一致；用例 A 的 RR 表按本文的顺序。
