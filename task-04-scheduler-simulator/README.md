# 调度实验台

操作系统进程调度可视化模拟器。调度核心在 `src/core`，不依赖界面。界面只把核心输出的时间片画成甘特图，并在图下印出同一串片段，例如 `P1[0,7) P2[7,11)`。半开区间 `[start, end)` 表示从时刻 start 执行到 end，不含 end。

规范原文在本目录的 `task-04-scheduler-simulator.md`。

## 如何运行

需要 Node.js 20 或更高版本。

```bash
cd task-04-scheduler-simulator
npm ci
npm run dev          # http://127.0.0.1:5173
npm run typecheck
npm test             # Vitest，核心与手算夹具
npm run build
npm run test:e2e     # Playwright，需先 build；会写 screenshots/
npm run test:all     # 类型检查 + 单元测试 + 构建 + 端到端
```

界面打开后默认是用例 A、先来先服务。可以改进程表、切换算法、单步或按速度播放，也可以在运行中追加进程。对比报告用当前进程表，从 t=0 把勾选的算法各自跑完。

## 调度约定

下面这几条是核心、手算夹具和界面共用的合同。`src/core/rules.ts` 里的 `RULES_SUMMARY` 是同一段话。

时间是离散整数。时刻 t 按这个顺序处理：

1. 到达时间等于 t 的进程，按 PID 升序，进入就绪队列队尾。
2. 抢占式算法检查就绪进程。只有主关键字**严格更优**才抢占。SRTF 比剩余时间，抢占式优先级比优先级数值，MLFQ 比是否存在更高队列。相等不抢占。
3. CPU 空闲则分派下一进程。
4. 执行区间 `[t, t+1)`。
5. 这一拍结束时：剩余时间到 0 则完成；否则若 CPU 进度到达 I/O 触发点则进入等待；否则若时间片用尽则让出 CPU。

时间片用尽发生在上一拍结束，所以让出的进程先入队，然后才处理时刻 t 的新到达。被抢占的进程也在时刻 t 的第 2 步入队，排在这一刻新到达的进程之前。

平局：先比较到达时间，更早者优先；到达时间也相同则 PID 更小者优先。FCFS 不看服务时间和优先级，只按入队顺序；同时到达时第 1 步已经按 PID 排好。

优先级数值越小越高。

甘特图的一段是一次分派。同一进程在时间片边界被再次分派时，两段不合并。连续空闲合并成一段。

指标：

| 指标 | 定义 |
| --- | --- |
| 周转时间 | 完成时间 − 到达时间 |
| 等待时间 | 停留在就绪态的时间，等于周转 − 服务时间 − I/O 时间。不含 I/O 阻塞，不含尚未到达的新建态 |
| 响应时间 | 首次获得 CPU 的时刻 − 到达时间 |
| CPU 利用率 | 忙碌时间 / 仿真时钟。时钟从 0 算到最后一个进程完成，开头和中间的空闲都算在分母里 |
| 平均值 | 只统计已完成进程。界面保留两位小数 |

没有 I/O 时，等待时间 = 周转时间 − 服务时间。夹具里的标准用例都没有 I/O，测试会先用这个等式检查预期结果自身，再和引擎比较。

动态添加：仿真还没走步时，使用填写的到达时间。时钟已经走动之后，早于当前时间的到达被调整到当前时间，进程仍是新建态，下一步才入队。未来到达保持原值。请求对象本身不会被改写。

## 算法

### 先来先服务 FCFS

就绪队列先进先出，不抢占。同时到达按 PID 升序入队。服务时间更短或优先级更高都不会插队。

### 短作业优先 SJF（非抢占）

只在 CPU 空闲时选择。比较的是**当前剩余 CPU 时间**（没有运行过、也没有 I/O 时等于服务时间）。剩余时间相同则先到达时间，再 PID。选中后一直运行到完成、进入 I/O，或仿真结束，中途不抢占。

### 最短剩余时间优先 SRTF

空闲时的选择规则与 SJF 相同。运行中，只有某个就绪进程的剩余时间**严格更短**才抢占。剩余时间相等时当前进程继续，即使对方 PID 更小。

### 时间片轮转 RR

就绪队列先进先出。时间片是整数，至少为 1，界面和对比报告都可以改，默认 2。时间片用尽后进入队尾，并清零已用时间片。若队列里只剩它自己，下一拍会再次分派，甘特图仍分成两段。I/O 返回后时间片重新计算，从队尾开始。

### 优先级（非抢占 / 抢占）

两种都要实现，界面里是两个独立算法。数值越小越高。空闲时选择最高优先级；平局先到达时间，再 PID。

非抢占：选中后不被后来的更高优先级打断。

抢占：只有就绪进程的优先级数值**严格更小**才抢占。数值相等不抢占。

### 多级反馈队列 MLFQ

默认 3 级，时间片 2 / 4 / 8。队列可以增加到 3 级以上，每级时间片是不小于 1 的整数。Q0 最高。

- 新进程进入 Q0 队尾。
- 时间片用尽：若不是最低级则降一级，已用时间片清零，进入该级队尾。最低级用尽后留在最低级队尾。
- 更高队列来了进程：当前进程回到**本队队首**，已用时间片保留，不降级。
- I/O 返回：留在原级，时间片清零，进入队尾。
- 分派时从最高的非空队列取队首。
- 进程属性里的优先级字段不参与 MLFQ。

## 用例 A：错开到达

| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 0 | 7 | 2 |
| 2 | 2 | 4 | 1 |
| 3 | 4 | 1 | 3 |
| 4 | 5 | 4 | 2 |

RR 时间片 2。MLFQ 时间片 2/4/8。没有 I/O。四个进程的服务时间之和是 16，每种算法都没有空闲，CPU 利用率为 100%。

### FCFS

P1 在 0 到达并运行到 7。P2、P3、P4 按到达顺序排在后面。P1 完成后依次运行 P2、P3、P4。

`P1[0,7) P2[7,11) P3[11,12) P4[12,16)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 7 | 7 | 0 | 0 |
| 2 | 11 | 9 | 5 | 5 |
| 3 | 12 | 8 | 7 | 7 |
| 4 | 16 | 11 | 7 | 7 |

平均等待 4.75，平均周转 8.75，平均响应 4.75。

### SJF（非抢占）

P1 从 0 运行到 7，中途不看新到达。t=7 时剩余时间是 P3=1、P2=4、P4=4。先选 P3。P2 与 P4 剩余时间相同，P2 到达更早。

`P1[0,7) P3[7,8) P2[8,12) P4[12,16)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 7 | 7 | 0 | 0 |
| 2 | 12 | 10 | 6 | 6 |
| 3 | 8 | 4 | 3 | 3 |
| 4 | 16 | 11 | 7 | 7 |

平均等待 4.00，平均周转 8.00，平均响应 4.00。

### SRTF

- t=0：只有 P1，剩余 7。
- t=2：P2 到达，剩余 4，P1 还剩 5。4 更小，抢占。P1 已运行 `[0,2)`。
- t=4：P3 到达，剩余 1，P2 还剩 2。抢占。P2 已运行 `[2,4)`。
- t=5：P3 完成。就绪进程剩余时间 P2=2、P4=4、P1=5，选 P2。P2 运行 `[5,7)` 后完成。
- t=7：P4 剩余 4，P1 剩余 5，选 P4，运行 `[7,11)`。
- t=11：P1 运行 `[11,16)`。

t=2 时两者剩余时间如果相等就不会抢占；这里是 4 < 5，所以抢占。

`P1[0,2) P2[2,4) P3[4,5) P2[5,7) P4[7,11) P1[11,16)`

| PID | 完成 | 周转 | 等待 | 响应 |
| --- | --- | --- | --- | --- |
| 1 | 16 | 16 | 9 | 0 |
| 2 | 7 | 5 | 1 | 0 |
| 3 | 5 | 1 | 0 | 0 |
| 4 | 11 | 6 | 2 | 2 |

平均等待 3.00，平均周转 7.00，平均响应 0.50。

### RR，q=2

队列变化（队首在左）：

| 时刻 | 发生的事 | 随后的队列 |
| --- | --- | --- |
| 0 | P1 入队并被分派 | 空 |

| 8 | P1 用尽，还剩 1 | 分派 P3，队列 `[P4, P2, P1]` |

| 3 | 9 | 5 | 4 | 4 |
| 4 | 16 | 11 | 7 | 4 |

平均等待 6.25，平均周转 10.25，平均响应 2.50。

### MLFQ，q=2/4/8

- `[0,2)` P1 用完 Q0，降到 Q1。
- t=2，P2 进入 Q0，运行 `[2,4)`，降到 Q1。此时 Q1 是 `[P1, P2]`。

- t=5，P4 进入 Q0，运行 `[5,7)`，降到 Q1。Q1 是 `[P1, P2, P4]`。
- P1 在 Q1 还剩 5，时间片 4，运行 `[7,11)` 后降到 Q2，还剩 1。
- P2 在 Q1 还剩 2，运行 `[11,13)` 完成。
- P4 在 Q1 还剩 2，运行 `[13,15)` 完成。
- P1 在 Q2 运行 `[15,16)` 完成。

`P1[0,2) P2[2,4) P3[4,5) P4[5,7) P1[7,11) P2[11,13) P4[13,15) P1[15,16)`

| --- | --- | --- | --- | --- |
| 1 | 16 | 16 | 9 | 0 |
| 2 | 13 | 11 | 7 | 0 |
| 3 | 5 | 1 | 0 | 0 |
| 4 | 15 | 10 | 6 | 0 |

平均等待 5.50，平均周转 9.50，平均响应 0.00。四个进程都在到达的那一拍立刻上了 Q0，所以响应时间都是 0。

## 用例 B：同时到达

| PID | 到达 | 服务 | 优先级 |

| 1 | 0 | 4 | 2 |
| 2 | 0 | 6 | 1 |

## 用例 C：单个进程

| PID | 到达 | 服务 | 优先级 |
| --- | --- | --- | --- |
| 1 | 4 | 5 | 2 |

`[0,4)` 是空闲。空闲不算等待。完成时间 9，周转 5，等待 0，响应 0。忙碌 5、时钟 9，CPU 利用率 5/9 = 55.56%。七种算法的这三个时间指标都一样，差别在甘特图是否因时间片被切开：

| 算法 | 甘特图 |
| --- | --- |
| FCFS、SJF、SRTF、两种优先级 | `空闲[0,4) P1[4,9)` |
| RR q=2 | `空闲[0,4) P1[4,6) P1[6,8) P1[8,9)` |
| MLFQ 2/4/8 | `空闲[0,4) P1[4,6) P1[6,9)` |

RR 三次分派是因为 q=2，最后一段只剩 1。MLFQ 先在 Q0 运行 2，再降到 Q1，剩余 3 小于该级时间片 4，所以第二段是 `[6,9)`。

## 动态添加与 I/O

用例 A 跑到 t=3 时加入 P5，请求到达时间 0、服务时间 2、优先级 1。因为时钟已经是 3，有效到达时间改成 3。FCFS 队列在 P1 完成后是 P2、P5、P3、P4：

`P1[0,7) P2[7,11) P5[11,13) P3[13,14) P4[14,18)`

P5 完成 13，周转 10，等待 8，响应 8。端到端测试检查这一段。

I/O 示例：P1 到达 0、服务 4，累计 CPU 满 2 后阻塞 3；P2 到达 0、服务 3。FCFS：

`P1[0,2) P2[2,5) P1[5,7)`

P1 完成 7、周转 7、等待 0、响应 0、I/O 3。P2 完成 5、周转 5、等待 2、响应 2。平均等待 1.00，平均周转 6.00，平均响应 1.00。阻塞的 3 个时间单位不算等待。t=2 这一拍结束时 P1 刚进入等待，P2 还在队首，下一步才分派 P2，最终甘特图里没有空闲段。

## 界面在检查什么

- 甘特图每一块的 `data-pid`、`data-start`、`data-end` 与核心片段一一对应，图下的文字是同一串片段。
- 同色块之间的空隙表示再次分派，不是空闲。空闲用斜线单独画出来。
- 当前运行进程、就绪队列队首、I/O 等待队列、每个进程的状态文字和状态泳道会随单步更新。
- 速度有暂停、慢放（2 秒一步）、正常（0.8 秒）、快进（0.12 秒），另有单步和运行至结束。
- 导出 JSON 是完整的 `SimulationResult`。导出 CSV 含 `process`、`slice`、`summary` 三种行；`cpu_utilization` 是 0 到 1 的比值，不是百分数。`summary` 的完成时刻在 `makespan` 列。
- 对比表和每张对比甘特图都从核心重新计算。改时间片后要点「生成对比报告」。加载用例 A/B/C 会把 RR 时间片恢复为 2，把 MLFQ 恢复为 2/4/8，不改当前选中的算法。

## 已知限制

- 只有一个 CPU，时间只能是整数。
- 界面上每个进程只能填一次 I/O。引擎可以接收同一进程的多次 I/O，触发点必须满足 `1 ≤ afterCpu < 服务时间`，且不能重复。
- I/O 返回后，RR 和 MLFQ 都重新计算时间片；MLFQ 不升回 Q0，也不降级。
- MLFQ 没有基于等待时间的老化，也不读取进程优先级。
- 导出和对比都按当前进程表从 t=0 重新跑完，不是把播放头截成半成品。动态添加过的进程使用调整后的到达时间。
- 平均指标在有进程完成之前显示为「—」。
- 同一拍里，时间片用尽或 I/O 结束先入队，这一拍的新到达排在后面。若按「新到达先于让出进程」来手算 RR，结果会和这里不一致；用例 A 的 RR 表按本文的顺序。
