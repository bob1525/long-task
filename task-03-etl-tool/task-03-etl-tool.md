# 任务 3：小型 ETL 工具（支持规则引擎与错误恢复）

## 任务目标

从零构建一个小型但严谨的 ETL（Extract-Transform-Load）工具。该工具必须支持多种数据源、可配置的转换规则、错误恢复机制，以及可视化的执行监控。重点在于正确性、可配置性和对异常数据的处理能力。

## 必须完成的功能

### 1. 数据提取（Extract）
- 支持至少 3 种数据源：CSV、JSON、SQLite
- 支持从本地文件和内存数据读取
- 支持基本的过滤条件（在提取阶段即可过滤行）

### 2. 转换引擎（Transform）
- 支持可配置的转换规则（通过 JSON 或 YAML 定义）
- 至少支持以下转换操作：
  - 字段重命名
  - 类型转换
  - 字符串处理（trim、大小写、替换）
  - 数值计算（简单表达式）
  - 条件映射（if-else 风格）
  - 字段合并 / 拆分
- 规则必须可组合、可排序
- 转换过程可追踪（记录每条规则对数据的影响）

### 3. 加载（Load）
- 支持输出到：CSV、JSON、SQLite
- 支持追加和覆盖模式
- 加载失败时支持回滚或记录失败批次

### 4. 错误处理与恢复
- 单条记录转换失败时不中断整体流程
- 失败记录单独收集并输出错误报告
- 支持配置“失败阈值”（超过一定比例则终止）
- 支持断点续传（记录已处理进度，可从中断处继续）
- 详细的错误日志（包含原始数据、失败规则、错误原因）

### 5. 监控与可视化
- 命令行进度显示
- 可选的简单 Web 界面：显示当前任务状态、处理进度、错误统计
- 执行报告：成功数、失败数、耗时、规则执行统计

### 6. 测试与质量要求
- 每种数据源的读写有测试
- 每种转换规则有单元测试
- 错误恢复和断点续传有专门测试
- 至少包含一个完整的端到端流程测试（含故意注入的错误数据）
- 测试覆盖率要求：核心转换逻辑 ≥ 80%

## 严格完成标准（全部满足才算完成）

1. 能够完成一个包含错误数据的完整 ETL 流程，并正确输出成功数据和错误报告
2. 断点续传功能经过测试验证
3. 所有转换规则按配置正确执行
4. 测试全部通过，核心逻辑覆盖率达标
5. 经过至少两轮审查：
   - 第一轮：实现基本流程
   - 第二轮：完善错误处理、边界情况和性能
6. README 包含配置示例、运行方式、规则语法说明

## 禁止事项

- 禁止在遇到错误数据时直接崩溃
- 禁止省略断点续传或错误收集
- 禁止规则引擎只支持硬编码转换

## 技术栈建议

- Python（推荐，数据处理生态好）或 TypeScript
- 配置使用 JSON / YAML
- 测试使用 pytest 或对应框架
