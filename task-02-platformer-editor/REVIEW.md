# 迭代记录

## 第一轮：游戏循环和编辑器

做出了固定时间步的平台跳跃、三种地形、金币和钥匙、巡逻敌人、终点条件、跟随摄像机，以及网格编辑器（涂抹、图层、试玩、JSON 导入导出、关卡列表、撤销）。三张内置关用同一份数据和同一套模拟。

这一轮对着实际移动和编辑核对时，改了下面几处：

1. **格子接缝把脚卡住。** 水平碰撞如果用全身高度，跑过两块紧挨着的地面时会撞上下一块的侧面，人会一下一下顿住。水平检测在脚底和头顶各留了 0.3 像素，不再把站立的接触面当成墙。`tests/physics.test.ts` 里 “keeps a constant foot line while running across tile seams” 连续走 180 步，脚的高度保持不变。从固体走到同一高度的单向平台也有同样的用例。
2. **高速下落穿过薄平台和危险区。** 只看这一帧的落点时，一次 800 像素以上的下落会跨过一格厚的地面、单向平台，或者整格危险区。`moveBody` 按起点到终点覆盖的格子解析竖直碰撞，危险区用移动前后的包围盒扫描。对应测试包括落地不穿透、薄单向平台接住高速下落、从下往上穿过单向平台，以及跨越危险区时判定失败。埋在固体地板下面的危险区不会误伤站在地板上的人。
3. **帧率改变落点。** 重力如果按渲染帧累加，30fps 和 120fps 跑出的水平位置不一样。模拟改成 1/120 秒的固定步长，渲染帧只把时间推进累加器。同一段输入在 30fps、60fps、120fps 下的位置被测试锁住。
4. **内置关卡一点击就被改掉。** 编辑器最初在指针按下时就复制内置关。误触也会生成「晨间小路 副本」，撤销栈也不再指向原来的内置关。改为这一笔结束、而且 `sameLevel` 确认内容和内置关不同时，才 `captureBuiltinEdit`。只是按下又松开、没有改到格子，内置关保持原样。

## 第二轮：手感复核和编辑器存档

第一轮的物理用例和三关回放在这一轮重新跑过，接缝、防穿透、单向平台、危险区和敌人碰撞仍然通过，没有再改积分方式，避免把已经录好的通关输入跑偏。试玩和端到端把问题指到了存档和列表：

1. **删除自定义关卡后它又出现，刷新也还在。** 端到端走到「确认删除」时，列表里的关卡名还在。原因是 `persist()` 在保存前发现当前关卡 id 不在数组里，就把它再插回去。删除刚刚把它滤掉，紧接着的保存又用编辑器里这份当前关卡补了回去，提示却写「已删除」。现在列表成员以数组为准：`applyCurrentToList` 只替换仍然存在的 id，不会把已删除的 id 复活。删除时先切到剩余关卡或内置关，再整表写回 `localStorage`。`tests/storage.test.ts` 覆盖「更新仍在列表中的关卡、不复活已删除 id」。
2. **还没松手，内置关卡的列表名就被改掉。** 在名称框里打字会立刻写进当前文档。列表渲染用「id 相同就显示文档里的名字」，所以内置关的按钮在副本生成之前就换成了新名字，看起来像原关被改写。列表现在只有自定义关卡显示编辑中的名字；内置关一直显示原名，松手并确认有改动后才出现副本。
3. **删除确认无法收回，也容易看漏。** 确认按钮和普通按钮一样，点下去就没有退路。加上「取消」、`Esc`，以及红底的确认区，说明这一步会同时从列表和浏览器存档里去掉。内置关的删除按钮保持禁用，并注明不能删除。
