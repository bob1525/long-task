# 任务 2：带关卡编辑器的 2D 平台跳跃游戏

## 任务目标

从零构建一个可玩的 2D 平台跳跃游戏，并配套一个功能完整的关卡编辑器。游戏必须支持自定义关卡的创建、编辑、保存和加载，且编辑器与游戏引擎共享同一套关卡数据格式。

## 必须完成的功能

### 1. 游戏引擎
- 玩家角色：左右移动、跳跃、重力、碰撞检测
- 至少 3 种地形类型：固体平台、可穿越平台、危险区域（接触即失败）
- 至少 2 种收集物：金币、钥匙
- 至少 1 种敌人或移动障碍
- 关卡目标：到达终点（可选要求收集一定数量物品）
- 摄像机跟随玩家
- 胜负判定与重新开始
- 物理手感可调（重力、跳跃高度、移动速度）

### 2. 关卡编辑器
- 可视化网格编辑界面
- 支持放置 / 删除：地形、收集物、敌人、起点、终点
- 支持图层或分类显示
- 实时预览（可在编辑器内直接试玩当前关卡）
- 关卡保存为 JSON 文件
- 关卡加载与列表管理
- 撤销 / 重做（至少支持最近 20 步）
- 网格对齐与基本对齐辅助

### 3. 关卡数据与兼容性
- 游戏和编辑器使用完全相同的关卡数据格式
- 编辑器导出的关卡可直接在游戏中加载运行
- 至少内置 3 个可玩示例关卡

### 4. 测试与质量要求
- 核心物理与碰撞逻辑有单元测试
- 关卡序列化 / 反序列化有测试
- 至少包含一个完整的“编辑 → 保存 → 加载 → 游玩”流程测试
- 游戏在常见分辨率下可正常显示和操作
- 无明显卡顿或碰撞穿透问题

## 严格完成标准（全部满足才算完成）

1. 玩家可以完整游玩至少 3 个关卡并到达终点
2. 编辑器可以创建新关卡、编辑、保存、重新加载后内容不丢失
3. 编辑器内的试玩功能正常工作
4. 撤销 / 重做功能可用
5. 所有核心测试通过
6. 经过至少两轮迭代：
   - 第一轮：实现基本游戏循环和编辑器
   - 第二轮：修复物理手感、碰撞问题、编辑器体验问题
7. README 包含操作说明、如何运行、如何创建关卡

## 禁止事项

- 禁止使用完整的游戏引擎框架（如 Phaser、Unity 导出等）作为核心实现，允许使用轻量渲染库
- 禁止关卡数据在编辑器和游戏之间不兼容
- 禁止省略碰撞检测或基本物理

## 技术栈建议

- TypeScript + HTML Canvas 或 WebGL
- 或 Python + Pygame（如选择桌面端）
- 关卡数据使用 JSON

## 交付物

- 可运行的游戏
- 功能完整的关卡编辑器
- 至少 3 个示例关卡
- 测试套件
- 操作说明 README

## 监督要求

本任务完成后，必须由监督者进行实际试玩验收。验收不通过（无法通关、编辑器数据丢失、碰撞异常等）则必须修复后重新提交。
