# 平台跳跃 · 关卡编辑器

从零实现的 2D 平台跳跃游戏和关卡编辑器。物理、碰撞和游戏循环都在本目录里，没有使用 Phaser 或其他完整游戏引擎。游戏和编辑器读写同一份关卡 JSON（`src/schema.ts`，格式版本 2）。版本 1 的文件在读入时自动补上移动平台、存档点和二段跳开关，并写成版本 2。

## 运行

```bash
cd task-02-platformer-editor
npm install
npm run dev
```

开发服务器默认是 [http://127.0.0.1:5173](http://127.0.0.1:5173)。构建后的静态页面：

```bash
npm run build
npm run preview
```

预览地址是 [http://127.0.0.1:4173](http://127.0.0.1:4173)。

## 怎么玩

- 方向键或 `WASD`：左右移动。按住下方向键或 `S` 可以落下单向平台，也可以从移动平台上跳下去。
- 空格、`W` 或上方向键：跳跃。按住跳得更高，点按会提前落下。顶栏勾选「二段跳」后，落地前可以再跳一次；这个开关写在关卡的 `physics.doubleJump` 里。
- 站在移动平台上会被平台带着走。平台沿路径来回移动，路径只能由水平段和垂直段组成。
- 碰到存档点之后，这次接触的存档点成为复活位置。再掉出关卡、碰到危险区或敌人时，从那里复活，已经拿到的金币和钥匙还在。还没碰到任何存档点时，死亡仍然直接失败。
- `R` 或「重新开始」：回到起点，并清掉当前存档点。
- 顶栏滑条可以当场改重力、跳跃高度和移动速度。在编辑器里改动的数值会写进关卡；在游戏里改的是当前这一局的手感。
- 左侧列表切换关卡。内置四关：
  - **晨间小路**：平地、缺口上的危险区和一段单向平台。
  - **断桥钥匙**：要跳上单向桥，拿到钥匙才能进终点。
  - **巡逻哨岗**：左右巡逻的敌人，加上缺口和单向平台。
  - **升降栈桥**：先乘水平渡船，再乘垂直升降台，途中有存档点，上层有一个会追踪的敌人。这关打开了二段跳。

## 怎么做一关

1. 打开「编辑器」，点「新建关卡」。新关自带一块地面、起点和终点。
2. 在工具栏选固体、单向、危险、金币、钥匙、敌人、追踪、存档、移动台、起点或终点，在网格上按住左键涂抹。右键或「橡皮」删掉地形、收集物、敌人和存档点。起点和终点各只有一个，再用对应工具点到新格子上就会移过去。
3. 「移动台」第一次点击放下一块平台，接着点击会把路径接到上一个点。斜着点时会收成水平或垂直的一段。
4. 拖动一笔算一步撤销。撤销 / 重做也可以用 `Ctrl/Cmd+Z` 和 `Ctrl/Cmd+Y`（或 `Ctrl/Cmd+Shift+Z`）。栈里至少保留 20 步，实际保留 80 步。
5. 数字键 `1`–`9` 和 `0` 切换原来的十个工具：选择、固体、单向、危险、金币、钥匙、敌人、起点、终点、橡皮。追踪、存档和移动台用工具栏按钮。
6. 「选择」工具点在物体上可以拖动它。在空地上拖出方框会选中框里的地形、收集物、敌人、移动台和存档点。拖动其中一个，框里的物体一起移动。`Ctrl/Cmd+C` 或「复制」复制选区（不含起点和终点），`Ctrl/Cmd+V` 或「粘贴」贴到光标所在格，新物体使用新的 id。选中敌人后，右侧能改巡逻范围、速度和追踪距离。
7. 勾选地形、收集物、敌人、标记、网格、对齐辅助，可以单独隐藏一类东西。对齐辅助会在光标与起点、终点或其他物体同一行或同一列时画出整列 / 整行。
8. 滚轮平移画布，按住空格再拖动也可以平移。
9. 「试玩」在编辑器里直接跑当前关卡。`Esc` 或「停止试玩」回到编辑。失败或过关后可以再试一次。
10. 「保存」写入浏览器 `localStorage`。编辑自定义关卡时，涂抹结束也会自动保存，但关卡不合格时这一步会被拦住。「下载 JSON」同样先做校验。校验失败时，底部列出起点缺失、终点缺失、终点从起点走不到、或钥匙数量少于 `requireKeys`，并标出格子坐标，画布上用红框圈出这些位置。试玩不受这道校验限制，方便先看问题出在哪。格式不对时，底部会写出具体原因，页面不会崩。版本 1 的 JSON 可以导入，读入后就是版本 2。
11. 「重命名」聚焦名称框。名称、宽高和终点需要的金币 / 钥匙都在右侧。需要的数量比关卡里实际放置的多时，会提示这关目前通不了。
12. 内置关卡不能直接改写，也不能删除。松手之后，如果内容真的变了，会另存成自定义副本，列表里的内置原名保持不变。自定义关卡用「删除」，再点「确认删除」；「取消」或 `Esc` 可以收回。

编辑器导出的文件和游戏列表用的是同一个 `parseLevel` / `serializeLevel`。导入后出现在游戏和编辑器两个列表里，选中即可开玩。

## 测试

```bash
npm test          # 物理、碰撞、序列化、撤销、存档、四关确定性通关，以及第三轮的新规则
npm run typecheck
npm run build
npm run test:e2e  # 先构建，再用 Playwright 跑编辑流程、第三轮和两种分辨率
npm run ci        # typecheck、单元测试、构建、端到端
```

端到端覆盖：新建关卡、放置、保存、刷新后内容一致、试玩走到终点；连续 20 步撤销和重做；图层和对齐辅助；非法 JSON 的错误提示，以及下载后再导入。分辨率检查是 1280×720 和 1920×1080。前三关通关由 `tests/playthrough.test.ts` 回放 `src/scripts.ts` 里的固定时间步输入，跑两遍，位置必须一致。第四关「升降栈桥」用同一份脚本，在 `tests/round3.test.ts` 里回放两遍，并确认途中乘上了渡船、升降台和存档点。

第三轮另外覆盖：版本 1 关卡迁移后仍能用原来的晨间小路脚本通关；移动平台带着人水平、垂直移动，走下平台和按住下键落下；追踪敌人在视野内靠近、视野外站着不动、碰到就失败；存档点复活并保留金币；二段跳抬高顶点，关闭时第二次按键无效；框选、复制粘贴、批量移动的撤销和重做；路径吸附；终点不可达和钥匙不足时指出坐标。Playwright 覆盖框选复制、校验拦住保存、第四关通关、版本 1 导入后试玩到终点。

`npm run record` 用来重新录内置关卡的通关输入（`scripts/record.ts`）。日常测试不用跑它。

GitHub Actions 工作流 `.github/workflows/task-02-platformer-editor.yml` 只在 `pull_request` 改到 `task-02-platformer-editor/**` 或该工作流文件时运行：安装、单元测试、类型检查、构建、Playwright，并上传报告和截图。

## 已知限制

- 敌人有两种。巡逻敌人仍在 `left`/`right` 格内左右走动。追踪敌人在玩家与自己的水平距离不超过 `sight` 格、并且垂直距离不超过 1.5 格时，朝玩家移动，速度是 `speed`，位置夹在 `left`/`right` 范围内；出了这个范围就站着不动。碰到任何敌人都会死。没有射击。
- 存档点记的是最近一次碰到的那个，不是离死亡位置直线距离最近的那个。
- 二段跳可以在上升过程中使用。冲刺没有做。
- 移动平台的路径必须水平或垂直。平台厚度是 10 像素，站在顶面上才会被带走。
- 起点和终点不能删掉，也不能被复制，只能移动。关卡格式要求各有一个。
- 校验只检查起点、终点、钥匙数量和格子层面的可达性。它不模拟敌人走位，所以一条“走得到”的关仍可能在实战里过不去。
- 撤销栈记录的是关卡内容。删除整关、切换关卡不会进撤销栈。
- 格子固定 32 像素。关卡最宽 200 格、最高 80 格。
- 没有音效、手柄和虚拟摇杆。编辑用鼠标或指针，游玩用键盘。
- 自定义关卡存在当前浏览器的 `localStorage`。换浏览器或清站点数据会丢，需要靠下载的 JSON 带走。
- 游戏模式里的物理滑条只影响正在玩的这一局；要写进文件，得到编辑器里调整并保存或下载。
