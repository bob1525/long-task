# 任务 1：交互式 Lisp 解释器 + 可视化执行环境

## 任务目标

从零构建一个功能完整、可交互的简化版 Lisp（Scheme 风格）解释器，并配套一个可视化执行环境。该系统必须能正确执行 Lisp 程序，并以可视化方式展示求值过程、环境链、调用栈和内存使用情况。

## 必须完成的功能

### 1. 核心解释器
- 支持基本数据类型：数字、布尔、字符串、符号、列表、过程（lambda）
- 支持特殊形式：`define`、`lambda`、`if`、`cond`、`let`、`let*`、`begin`、`quote`、`set!`
- 支持基本内置函数：算术运算、比较运算、列表操作（`cons`、`car`、`cdr`、`list`、`null?`、`pair?`）、类型判断
- 正确实现词法作用域和环境链
- 支持递归和尾调用优化（至少识别并优化简单尾调用）
- 完整的错误处理：语法错误、运行时错误、未定义变量、类型错误，错误信息必须包含位置信息

### 2. 解析器
- 手写递归下降解析器或 Pratt 解析器（禁止直接使用现成的 Lisp 解析库）
- 支持注释（`;` 行注释）
- 支持引号简写（`'expr` 等价于 `(quote expr)`）
- 解析错误必须给出具体位置和原因

### 3. 可视化执行环境（Web 前端）
- 代码编辑器（支持语法高亮）
- 单步执行 / 连续执行 / 重置
- 实时展示：
  - 当前求值的表达式
  - 环境链（每一层绑定的变量和值）
  - 调用栈
  - 输出区域
- 支持在执行过程中查看任意环境帧的内容
- 执行历史记录（可回溯查看之前的步骤）

### 4. 测试与质量要求
- 单元测试覆盖：解析器、求值器、特殊形式、内置函数、错误情况
- 至少 40 个测试用例，全部通过
- 包含边界测试：空列表、深层嵌套、递归深度、错误恢复
- 端到端测试：通过前端执行至少 5 个完整示例程序并验证结果
- 代码必须有清晰的模块划分和类型注解

## 严格完成标准（全部满足才算完成）

1. 所有测试通过，无跳过、无跳过注释
2. 解释器能正确运行以下程序并得到预期结果：
   - 阶乘（递归）
   - 斐波那契
   - 列表反转
   - 简单高阶函数（`map`、`filter` 的手动实现）
   - 闭包示例
3. 可视化环境能正确展示上述程序的执行过程
4. 错误处理完整，不会因异常输入崩溃
5. README 包含：架构说明、如何运行、测试命令、已知限制
6. 经过至少两轮自我审查：第一轮实现核心功能，第二轮修复边界问题和优化可视化

## 禁止事项

- 禁止使用现成的 Lisp / Scheme 解释器库作为核心
- 禁止在测试失败时修改测试以通过
- 禁止省略错误处理或可视化的关键部分

## 技术栈建议

- 前端：React 或纯 HTML + Canvas / SVG
- 测试：对应语言的标准测试框架
