# 自我审查

## 第一轮：核心功能

实现了词法分析、手写解析器、显式栈求值器、内置函数、执行会话和可视化前端，并写了单元测试。

第一次 `npx vitest run` 的结果是 72 通过、2 失败、0 跳过。两处失败都是断言写错，解释器的结果符合 Scheme 语义，没有为了通过去改语义。

1. 闭包示例的期望写成了 `16`。程序最后一行是 `(+ (add5 1) (add10 1))`，即 `(5 + 1) + (10 + 1) = 17`。`tests/evaluator.test.ts` 的期望改为 `17`。
2. `execute('@')` 被期望成语法错误。`@` 不是分隔符，词法上是一个符号，求值时是未定义变量。断言改为「未定义变量」，并另加 `` `x ``，确认反引号仍然是语法错误。词法器没有为了迁就旧断言把 `@` 判成非法字符。

同一轮里尾递归 `(sum 100000 0)` 得到 `5000050000`，`maxCallStack === 1`，约 246ms。`npx tsc --noEmit` 通过。

## 第二轮：边界与可视化

对照界面操作和边界输入再查了一遍，修了下面这些：

1. **语法错误之后单步按钮一直禁用。** 错误快照被当成终态，即使用户已经改了编辑器。现在缓冲区相对上次执行是脏的时候，单步会重新启用，并用新源码重建会话。`e2e/programs.spec.ts` 覆盖：制造语法错误后输入一个字符，单步变为可用，再切回阶乘仍得到 `3628800`。
2. **当前动作放在全大写的面板标题里**，字母间距把动作拉开了。动作改到正文；尾调用用绿色标出。环境链标题写明「由内到外」。
3. **补上的边界测试**（`tests/edge.test.ts`）：空字符串、列表内部的行注释、跨行字符串、`let` 遮蔽内置 `+`、对形参 `set!`。
4. **示例的栈深被测试锁住。** 阶乘 `(factorial 10)` 的可视化最大栈深是 11（`n` 从 10 走到 0）。列表反转是尾递归，最大栈深是 1。如果尾调用被错误地套到非尾递归上，阶乘的栈深会掉下来，测试会失败。
5. **五个示例的可视化步数**：阶乘 290、斐波那契 4244、反转 167、map/filter 506、闭包 195。都低于 `session.ts` 里 80000 的历史上限，连续执行后可以回溯每一步。
6. **渲染异常不再直接白屏。** `src/main.tsx` 的错误边界接住渲染错误；求值循环里的异常由 `App` 接住并显示。`execute` 对畸形输入返回错误结果，不向外抛。

测量步数用过一个临时测试，确认后已删除，没有留在套件里。

7. **端到端里用 `insertText('(')` 直接替换全文没有生效。** CodeMirror 只认自己的选区；Playwright 的 `insertText` 插在光标处，整段阶乘被多包了一层括号，求值变成「调用未指定值」的类型错误。测试改为先 `Control+a` 再 Backspace 清空，然后输入 `(`。编辑器本来就绑定了 selectAll，这是测试操作方式的问题，不是把断言改弱。

## 第三轮（监督者打回）

1. **CI。** 增加 `.github/workflows/lisp-interpreter.yml`。只在 `task-01-lisp-interpreter/**` 或这个 workflow 文件变更的 pull request 上运行。干净环境里依次 `npm ci`、`npm test`、`npm run typecheck`、`npm run build`、安装 Chromium、`npm run test:e2e`，并把 Playwright HTML 报告、失败截图和单步截图上传为 artifact。
2. **失控递归和历史。** 非尾调用栈深度上限定为 512，写在 `src/lisp/limits.ts` 和 README。`(define (g) (+ 1 (g))) (g)` 在大约 4100 步时停住，错误指向第 2 行第 8 列的 `(g)`。尾递归死循环不增加栈深，停在步数上限，位置指向循环调用。可视化步数上限是 20000，和 `execute` 的 500 万步分开，避免界面为了批处理上限去存几百万张快照。历史从「满了就用一条含糊的错误停住」改成滑动窗口：只保留最近 6000 步，页面提示已丢弃的步数。`session.run` 不再用一个比历史上限更大的 100000 次循环把行为留成未定义。
3. **错误位置。** 语法、运行时、未定义变量、类型、参数个数、除零、步数超限、栈深超限都断言了具体行列。函数体在第 2 行的 `(/ x 0)` 从第 5 行调用时，位置指向第 2 行第 3 列，因为出错的是函数体里的表达式，调用本身是合法的。错误面板沿用「第 L 行, 第 C 列」的文案，并带上 `data-line` / `data-column`。编辑器用 `.cm-eval-error` 高亮这个区间；零宽度的错误至少标出一个字符。
4. **存活环境帧。** 快照会沿着过程的捕获环境和点对把所有还能碰到的环境帧收进来，而不只是当前链和调用栈。环境面板增加「所有存活帧」。绑定里的过程值可以点击，跳到它捕获的环境。闭包示例跑完后能看到 `make-adder` 的 `n = 5` 和 `n = 10`，以及两个计数器 `let` 帧里的 `n = 2` 和 `n = 1`。
5. **五个示例的单步断言。** 端到端不再只看最终结果。每个示例都在调用栈出现对应过程时检查当前表达式和参数绑定，并各存一张截图。反转在连续单步中保持最大栈深 1。阶乘跑完后最大栈深是 11。

这一轮没有为了通过去改掉已有的期望值。参数个数和调用非过程两条是在原来的断言上补了行列，原来的种类和文案检查还在。

## 第四轮（升级）

验收通过之后补了可变参数、命名 `let`、`do`、准引用、`and` / `or`、字符串和列表函数、断点、后退和地址栏恢复。实现过程中碰到并修了这些：

1. **旧测试把还没实现的语法当成错误。** `tests/parser.test.ts` 断言 `` `x `` 抛出准引用错误，`tests/errors.test.ts` 断言 `execute('`x')` 是语法错误，`tests/evaluator.test.ts` 断言 `(let loop ((a 1)) a)` 是语法错误。这三处和这次要做的语言冲突。测试没有删，也没有放宽别的断言：悬空反引号 `` ` `` 仍然必须报准引用错误；`execute('`')` 仍然必须是语法错误；命名 `let*` 仍然必须是语法错误。能运行的 `` `x `` 和 `(let loop ((a 1)) a)` 放进 `tests/upgrade.test.ts`。
2. **`do` 不能直接展开成名叫 `do-loop` 的命名 `let`。** 步进表达式会调用这个名字。用户如果写 `(do ((do-loop 0 (+ do-loop 1))) ...)`，递归调用会找到数字而不是循环过程。循环名从 `do-loop` 开始，和绑定冲突就改成 `do-loop*`。`tests/upgrade.test.ts` 用这个例子得到 `3`，并用 1000 次循环确认最大栈深是 1。
3. **`apply` 不能做成返回值的普通内置函数。** 那样尾位置的 `(apply sum ...)` 会先返回，再无法替换当前栈帧。求值器在调用名为 `apply` 的内置过程时先展开最后一个真列表，再按原来的尾标记调用目标过程。`(sum 3000 0)` 的最大栈深是 1；如果这里漏了尾调用，512 的栈上限会先报错。
4. **准引用不能展开成用户的 `cons` / `append`。** `(let ((cons 'no)) `(a ,(+ 2 3)))` 必须得到 `(a 5)`。展开在求值器里直接 `consPair`。`unquote-splicing` 单独出现，或者结果不是真列表，都是带位置的错误。
5. **命名 `let` 的初始值必须在外层求。** 循环过程放进一个新帧，初始值算完后用 `let` 自己的尾标记去 `apply`。因此顶层 `(let loop ((i 100000) (acc 0)) ...)` 第一次调用压入一帧，之后的递归替换这一帧。实测最大栈深 1，约 267ms。
6. **`and` / `or` 只有最后一个参数继承尾标记。** 中间参数一律不是尾位置，否则短路前的调用也会被错误优化。`(and (> n 0) (f (- n 1)))` 和 `(or (= n 0) (g (- n 1)))` 各跑 100000 次，最大栈深都是 1。
7. **断点不能把程序标成已修改。** 点行号只切换断点集合，不改文档，所以下一次连续执行不会从头开始。连续执行每走一步都看当前表达式的行。停住时机器状态仍是 `running`，再按一次从原栈继续；如果还停在同一行，会先离开这一行再允许下一次断点。`(define (f n) n) (f 1)` 把断点放在第 2 行，会停在调用栈里的 `f` 和当前表达式 `n`，结果还不是 `1`。
8. **地址栏要用原始 hash，不能用已经解码的 `location.hash`。** 浏览器会把 hash 解一次。源码里如果本身有 `%`，再 `decodeURIComponent` 一次就会损坏。读写都走 `location.href` 里仍然编码着的那一段。空地址继续打开阶乘示例，已有的端到端测试不用改。
9. **后退 200 步的端到端比较不能用 `toHaveText` 对多行环境链。** 环境链的 `innerText` 带换行，`toHaveText` 拿到的是去掉换行的文本，同样的内容会对不上。断言改成两边都读 `innerText`。求值器的历史本身没有问题：单元测试把光标往前走 200 步再退回，调用栈、当前表达式和活动帧绑定都与标记点一致，历史长度仍大于这个位置。
